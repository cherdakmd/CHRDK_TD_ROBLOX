# Архитектура и протокол

## Фазы матча

```text
Lobby → Combat → Intermission → Combat → … → Victory/Defeat → Lobby
```

- `Lobby`: 45 секунд, строительство разрешено. Если готовы все игроки, старт ускоряется до 6 секунд. Отмена готовности возвращает разумную задержку.
- `Combat`: детерминированный план волны, спавн по времени, движение по общему пути, стрельба башен, урон ядру.
- `Intermission`: 22 секунды на улучшения. Большинство может сократить ожидание до 2 секунд.
- `Victory/Defeat`: 30 секунд результатов, голосование за рестарт или автоматический возврат в лобби.

Серверный цикл работает фиксированными шагами 20 Hz. Состояние UI реплицируется 5 Hz. Эффекты передаются батчами. Ускорение 2× умножает шаг симуляции, но не частоту серверного цикла.

## RemoteEvents

Папка: `ReplicatedStorage/TD_Remotes`.

### `Action` — клиент → сервер

Сообщение: `{ kind: string, ...поля }`.

| kind | Поля | Проверки сервера |
|---|---|---|
| `Hello` | — | игрок загружен |
| `Ready` | `ready: boolean` | фаза Lobby |
| `Difficulty` | `value: "Normal" \| "Hard"` | фаза Lobby |
| `Build` | `padId: integer`, `towerType: string` | фаза строительства, площадка свободна, тип известен, хватает золота |
| `Upgrade` | `padId` | владелец, уровень < IV, хватает золота |
| `Sell` | `padId` | владелец, возврат 70% |
| `Priority` | `padId`, `value` | владелец, приоритет из списка |
| `Speed` | `value: 1 \| 2` | Combat/Intermission, большинство |
| `Skip` | — | Intermission, большинство |
| `Replay` | — | Victory/Defeat, большинство |
| `Ability` | `ability`, `target: Vector3` для метеора | Combat, общая перезарядка, конечные координаты внутри карты |

Лимит: token bucket, 12 действий в запасе, восстановление примерно 8 действий/с. Некорректные действия не меняют состояние и возвращают подсказку через `Notice`.

### `State` — сервер → клиент

Персональный снимок: фаза, волна, ядро, золото игрока, список отряда, готовность, скорость, перезарядки способностей, предпросмотр следующей волны, результаты, версия.

Владелец/тип/уровень/приоритет/вложения башни дополнительно реплицируются атрибутами площадки `Pad_XX`, чтобы клиент мог обновлять инспектор без отдельного запроса.

### `Effects` — сервер → всем клиентам

Батч визуальных событий: `Sentry`, `Cannon`, `Frost`, `Tesla`, `Chain`, `Meteor`, `Freeze`, `Defeat`, `Build`, `CoreHit`. Клиент создаёт временные локальные Part/Tween. Урон уже применён сервером; задержка снаряда — только визуальная.

### `Notice` — сервер → клиенту/всем

Короткие сообщения: ошибка действия, награда за волну, старт волны, способность, победа/поражение, статус сохранения.

## Боевая модель

- Путь общий (`Shared/Path.luau`) и используется картой, движением врагов и мини-картой.
- Радиусы башен считаются в плоскости XZ; летающие враги визуально выше, но Мортира их не выбирает.
- Броня вычитается из каждого попадания, минимум 1 урона.
- Урон по площади имеет спад до 35% на краю радиуса.
- Цепная молния теряет 22% урона на каждом следующем прыжке.
- Замедление не складывается бесконечно: применяется более сильный коэффициент, боссы имеют сопротивление.
- Награда за врага равна его bounty и делится по фактически нанесённому урону. Добивание даёт счётчик добиваний и остаток округления, но не крадёт всю награду.

## DataStore

Имя: `CHRDK_TD_Profile_v1`, ключ: `u_<UserId>`.

Поля:

```lua
{
  schema = 1,
  xp = 0,
  wins = 0,
  bestWave = 0,
  kills = 0,
  matches = 0,
  lock = { id = "<guid>", expires = <unix seconds> } -- только в облаке
}
```

Правила:

1. Загрузка через `UpdateAsync` атомарно ставит lock на 180 секунд.
2. Живой чужой lock → игрока не пускают, данные не меняются.
3. Ошибка загрузки → временный профиль без права записи.
4. Автосохранение раз в 60 секунд продлевает lock и пишет снимок.
5. Выход/`BindToClose` пишет финальный снимок и снимает lock.
6. Если lock потерян, дальнейшие записи запрещаются.
7. Если игрок вышел во время начальной загрузки, сервер не добавляет его в матч и освобождает только что полученный собственный lock.

В Studio (`RunService:IsStudio()`) используется временный профиль, чтобы локальные тесты не требовали API-доступа и не перезаписывали облако.

## Ограничения текущей версии

- Одна карта и один набор декораций.
- Нет матчмейкинга: игроки попадают на обычный сервер Roblox до 4 человек.
- Постоянный прогресс даёт уровень и статистику, но не боевое преимущество.
- Нет внешних звуковых ассетов: звук можно добавить отдельным слоем, не меняя боевую логику.
- Headless mock проверяет код и протокол, но не заменяет тест в настоящем Roblox Studio.
